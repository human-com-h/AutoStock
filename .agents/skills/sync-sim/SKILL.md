# 同步场景模拟

## 现状

依赖任务 **3.1～3.6**（change_seq、push、pull、LWW 合并、冲突记录）尚未实现前，本 Skill 只做检查与引导。

## 执行步骤

1. 检查后端同步相关路由（`/api/sync/push`、`/api/sync/pull`）与 `sync` 服务模块是否存在；不存在则说明阶段三尚未开工，询问用户是否先看《系统设计说明书》§7 与开发任务拆分的阶段三部分。
2. 若已实现，构造至少以下三类场景（对应 §13 同步测试用例），每类用一个独立的测试数据库或事务回滚保证可重复运行：
   - **场景 A（概要 4.1）**：设备 1（PC）对零件 A 入库 100，设备 2（手机）对零件 A 出库 5，两边互不知情后依次 push+pull，断言最终库存 = 原库存 + 95，且过程中不存在"覆盖"而是"相加"。
   - **场景 B（双端同改主数据）**：两台设备在断连期间修改同一 `part` 的不同字段，比较 `updated_at`，断言胜出方符合 LWW 规则（时间大者胜，相等 PC 胜），且败方整行被写入 `sync_conflict`。
   - **场景 C（删除 vs 修改）**：一端软删除某零件，另一端同时修改该零件字段，断言按 §7.3 "墓碑与修改同规则比较 updated_at"，而不是"删除总是赢"。
3. 对每个场景打印：推送批次内容摘要、服务端 `accepted`/`rejected`/`conflicts` 返回、拉取到的增量、最终双端状态是否一致。
4. 额外验证幂等性：同一 `client_batch_id` 重复推送两次，断言第二次不产生重复数据。
5. 任何断言失败时，明确指出是协议实现问题还是合并规则理解偏差，并引用对应设计文档章节号。
