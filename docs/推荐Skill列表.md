# AutoStock 推荐 Skill 列表

## 直接可用的内置 Skill

| Skill | 用途 | 触发场景 |
| --- | --- | --- |
| dataviz | 图表设计规范 | 做第 10 节的 ECharts 报表（折线/柱状/饼图/横向条形）时，写图表代码前先过一遍，保证四类图配色和交互风格统一 |
| run | 启动并验证应用 | 改完接口或页面后，实际启动 uvicorn 与两个前端确认改动生效，而不是只看单测通过 |
| security-review | 安全走查 | 鉴权模块（§8.1）、同步接口（§7.2）、证书/CA 生成（§14.2）这几块改动后必须跑一次，这是本项目里少数真正涉及攻击面的代码 |
| code-review / review | 代码走查 | 库存计算、同步合并这类错一点全盘账目就错的逻辑，合并前走查一次 |
| simplify | 复用/简化 | 两端各自实现的库存扣减、单据校验逻辑写完后，检查能否进一步收敛到 packages/shared |
| init | 生成/更新 CLAUDE.md | 后续架构决策变化时用它辅助更新本文档 |
| update-config | 配置 hooks/权限 | 例如把"提交前必须跑对账脚本"配置成 pre-commit hook 时使用 |

## 建议新建的项目自定义 Skill

以下是本项目特有的重复性操作，建议后续在 .claude/skills/ 下补充为具体技能：

| 建议 Skill 名 | 用途 | 理由 |
| --- | --- | --- |
| reconcile | 一键跑库存一致性对账脚本并汇总差异 | 设计文档 §13 强调这是最重要的一条测试，应该做到一条命令就能跑，而不是每次现写查询 |
| sync-sim | 模拟双端离线操作后触发同步，打印合并结果 | §7/§13 的同步测试场景（两端同改一个零件、离线后批量同步等）重复性高，适合固化成技能而不是每次手动摆测试数据 |
| cert-check | 检查本地 CA、服务器证书 SAN、过期时间、8756/8757 端口连通性 | 第 14 章的证书链路是本项目最容易出环境问题的部分，需要能快速自检 |

优先级建议：reconcile 和 cert-check 在阶段一/阶段二末尾就建好；sync-sim 在阶段三开工前建好。

## 安装状态（2026-07-27）

三个仍适用的自定义 Skill 骨架位于 `.claude/skills/<name>/SKILL.md`：`reconcile`、`cert-check`、`sync-sim`。

它们目前只有"检查依赖是否就绪 + 引导实现/引用设计文档章节"的逻辑，因为各自依赖的脚本/接口还没写（分别对应任务 1.2.5、2.1、3.1～3.6）。等对应任务完成后，这些 Skill 会自动检测到脚本/接口已存在并按预定步骤执行，不需要重新创建 Skill 文件，最多补充细节。
